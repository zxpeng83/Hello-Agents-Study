# 第四章学习疑惑与解答

本文件整理阅读[第四章 智能体经典范式构建](<../../hello-agents/docs/chapter4/第四章 智能体经典范式构建.md>)时的疑惑及讨论结果。以下保留各次讨论的问答形式、完整解释、例子与表格，仅对措辞和排版进行整理。

## 1. 4.3 的 Plan-and-Solve 没有调用工具，是否意味着它不适合调用工具？

**问：4.3 提到的 Plan-and-Solve 方案，并未涉及 4.2 中调用工具的功能。这是否意味着 4.3 的方案不适合调用工具？还是我哪里理解错了？**

**答：** 你的观察是对的：**4.3 的示例没有调用工具，但不代表 Plan-and-Solve 不适合调用工具。** 这里要区分“范式如何组织任务”和“执行步骤时具备什么能力”。

### （1）教材没有使用工具，是为了突出先规划、后执行的流程

教材在 **4.3.2“规划阶段”** 明确说：

> 为了凸显 Plan-and-Solve 范式在结构化推理任务上的优势，我们将不使用工具的方式，而是通过提示词的设计，完成一个推理任务。

这是为了简化示例，突出“先规划、后执行”的流程。

本节使用苹果销量应用题：先让模型生成计算计划，再让模型逐步求解。这个示例没有给执行器接入搜索、计算器等外部工具，但这只是本章示例的实现选择，不是 Plan-and-Solve 范式的能力限制。

### （2）两节的主要区别，是如何决定和执行下一步

| 对比项 | 4.2 ReAct | 4.3 Plan-and-Solve |
| --- | --- | --- |
| 如何决定下一步 | 根据已有结果，每轮决定下一步行动 | 先生成完整计划，再依次执行 |
| 本章如何执行 | 模型输出 `Action`，程序解析后调用工具 | 每一步直接调用模型求解 |
| 能否接入工具 | 已经接入 | 可以，但示例没有实现 |

**Plan-and-Solve 主要回答“任务按什么步骤推进”，工具调用回答“某个步骤具体怎么完成”。** 这两个问题处于不同层面，两者可以搭配。

例如，一个步骤可以通过模型直接推理完成，也可以通过调用外部工具完成；这些执行方式都可以放进“先规划、后执行”的整体流程里。

### （3）例子：先规划，再调用天气工具和计算工具

比如用 Plan-and-Solve 回答：

> 北京和上海今天的温差是多少？

可以先生成计划：

```text
1. 查询北京今天的气温
2. 查询上海今天的气温
3. 计算温差并回答
```

随后，执行器按顺序完成计划：

- **步骤 1：** 调用天气工具，获得北京的气温。
- **步骤 2：** 调用天气工具，获得上海的气温。
- **步骤 3：** 使用前两步获得的数据，调用计算工具计算温差，并组织回答。

实际查询时，需要使用相同的时间和温度口径，例如比较同一时刻的气温，或比较当天的最高气温，避免把不同口径的数据直接相减。

**先规划再执行的结构保持不变，只是执行器增加了工具调用能力。** 前面步骤获得的结果仍然需要保存，并作为后续步骤的输入。

### （4）Plan-and-Solve 还可以与 ReAct 组合

还可以让 Plan-and-Solve 负责整体任务安排，让 ReAct 负责完成每个具体步骤：

```text
Planner 制定整体计划
    ↓
ReAct 执行步骤 1：根据需要调用工具，观察结果，继续行动
    ↓
ReAct 执行步骤 2
    ↓
……
汇总结果
```

这里有两层控制流程：

- **整体层面：** 根据事先生成的计划，依次推进各个步骤。
- **单个步骤内部：** ReAct 根据工具返回的结果，决定继续查询、调整行动，还是结束当前步骤并返回结果。

例如，整体计划要求“查询北京今天的气温”，但第一次查询没有获得有效结果，那么负责这个步骤的 ReAct 可以调整查询方式，再次调用工具，直到完成当前步骤或达到预设上限。

这类组合中，当前步骤内部的动态调整，不自动意味着整体计划也会修改。如果希望执行中能够调整后续计划，还需要另外设计动态重规划机制。

### （5）对应到本章代码，应该扩展哪里？

对应到 [Plan_and_solve.py](../../hello-agents/code/chapter4/Plan_and_solve.py)，可以扩展 `Executor.execute()`。

当前实现中，执行器遍历计划，为每个步骤组织提示词，然后调用 `llm_client.think()` 获取该步骤的回答，并把结果写入历史记录，供后续步骤使用。

要增加工具能力，可以采用两种方式：

1. **在执行器中加入工具调用流程。** 让模型输出工具指令，程序进一步解析指令，通过 `ToolExecutor` 执行工具，再把工具结果传回模型，由模型继续处理当前步骤。
2. **把当前步骤交给一个 `ReActAgent`。** 执行器负责提供任务上下文，ReAct 负责当前步骤内的工具选择、调用与结果处理，完成后将结果交回执行器。

第二种方式需要把原始问题、当前步骤及相关的历史结果传给 ReAct，确保它具备完成该步骤所需的信息。随后，执行器继续保存结果并推进下一步。

无论采用哪种方式，都要记住：**模型输出工具指令，真正调用工具的是 Python 程序。** 仅仅在计划中写下“查询天气”，并不会自动发生天气查询，还需要程序接入并执行对应工具。

因此，4.3 展示的是一个没有接入外部工具的 Plan-and-Solve 教学实现；这个范式本身可以搭配工具调用，也可以与 4.2 的 ReAct 组合使用。
