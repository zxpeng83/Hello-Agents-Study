# 第三章学习疑惑与解答

本文件整理阅读[第三章 大语言模型基础](<../../hello-agents/docs/chapter3/第三章 大语言模型基础.md>)时的疑惑及讨论结果。以下保留各次讨论的问答形式、完整解释、例子与表格，仅对措辞和排版进行整理。

## 1. 读不懂 3.1 节，怎样结合例子建立总体理解？

**问：阅读《第三章 大语言模型基础》时，我发现自己很难理解 3.1 节“语言模型与 Transformer 架构”。能否结合具体例子，用通俗的语言讲解这一节，帮助我理解主要概念及它们之间的联系，先建立整体认识？**

**答：** 读 3.1 时，你先抓住贯穿整节的一个问题：

**给计算机一段文字，它怎么利用前面的内容，预测接下来该写什么？**

N-gram、RNN、Transformer，就是围绕这个问题逐步发展起来的不同方法。下面按教材顺序讲，先理解思路，公式和代码可以暂时放下。

### （1）语言模型：先从“接着写”理解

假设输入是：

> 小明口渴了，于是他拿起杯子，喝了一口____。

你很容易想到“水”，因为前面的“口渴”“杯子”“喝”提供了线索。

语言模型要做的，就是根据已有文字，给可能接上的内容分配概率。例如：

| 候选内容 | 假设的概率 |
| -------- | ---------: |
| 水       |        70% |
| 茶       |        20% |
| 牛奶     |         9% |
| 其他     |         1% |

这些数字只是演示，不是实际模型结果。

模型根据这个概率分布选择接下来的内容，再继续预测，就能逐渐生成一段话。

这里先补一个概念：**模型实际处理的单位叫 token，可以暂时理解成“文字小块”**。一个 token 不一定对应一个汉字或一个完整单词。为了方便，下面仍然经常用“词”来举例。

那么，第一个问题来了：这些概率从哪里来？

### （2）N-gram：先试试“数以前出现过多少次”

最直接的方法是：看大量文本，统计某个词后面经常出现什么。

假设训练材料里，“喝”后面的内容是：

- “喝水”出现了 70 次。
- “喝茶”出现了 20 次。
- “喝牛奶”出现了 10 次。

那么，只看“喝”这个词，就可以估计下一个词是“水”的概率为 70%。

这就是教材中“计数除以计数”的直观含义。

**N-gram 的关键限制是：只看前面固定数量的词。**

例如：

- Bigram：看前面 1 个词，预测下一个词。
- Trigram：看前面 2 个词，预测下一个词。

为什么只看这么少？因为如果要求“前面整段话完全一样”才能统计，许多情况根本找不到足够的例子。

你可以把它想成一张很大的“接词统计表”。

但它有两个明显问题：

第一，**看得太近，容易丢掉远处的线索**。“小明口渴了”可能已经超出它考虑的范围。

第二，**不容易把相似情况联系起来**。即使见过很多“喝茶”，也不会仅凭这种计数方法，就自动理解“饮茶”与它意思相近。

这就引出了下一步：能不能让计算机用某种方式表示词的含义？

### （3）词向量和神经网络：把文字变成可以计算的数字

教材里的“词嵌入”“Embedding”“词向量”，在这里指向同一个核心想法：

> 用一串数字表示一个词，让模型能够计算词与词之间的关系。

例如，示意性地写成：

```text
水   → [0.2, 0.8, 0.1, ...]
茶   → [0.3, 0.7, 0.2, ...]
汽车 → [0.9, 0.1, 0.6, ...]
```

这些数字不是我们手工给词填写的“含义说明书”，通常也不能直接说某一位就是“能不能喝”。

**它们是在训练过程中逐渐调整出来的。** 某些词如果在用法、语义上有关联，模型就有机会学到它们之间的关系。

“向量”这个词现在不用怕：先把它理解成“一串数字”就够了。

有了这些数字，神经网络就可以学习：

```text
前面几个词的数字表示
        ↓
经过一系列可调整的计算
        ↓
下一个词的概率
```

所谓“训练”，可以粗略理解为：**反复练习预测，对照真实的下一个词，调整内部参数，让预测逐渐变好。**

这样，模型就有机会把学到的规律用于没见过的组合，而不只是查完全相同的词组出现了多少次。

不过，教材这里介绍的早期前馈模型，依然只接收固定数量的前文。我们还需要一种办法，让更早的信息传下来。

### （4）RNN 和 LSTM：一边阅读，一边更新“笔记”

RNN，也就是循环神经网络，可以想象成一个逐词阅读的人，手里始终拿着一张笔记：

```text
读到“小明” → 更新笔记
读到“口渴” → 结合旧笔记，再更新
读到“杯子” → 结合旧笔记，再更新
读到“喝”   → 利用此时的笔记预测后文
```

这张“笔记”在模型里就是**隐藏状态**，本质上仍然是一串数字。

与前面固定看几个词的方法相比，RNN 可以不断往下读，让早先的信息通过隐藏状态传递过来。

困难在于：**笔记容量有限，又被不断更新，较早的信息可能难以保留和利用。** 训练时，它也可能很难学会“很久以前的那个词，对现在的预测很重要”。

教材中的“长期依赖”“梯度消失”，就与这类困难有关，现在不必先推导。

LSTM 是对 RNN 的改进：给笔记增加更精细的管理机制。

| 教材里的名称 | 可以先这样理解           |
| ------------ | ------------------------ |
| 遗忘门       | 哪些旧信息可以减少或丢掉 |
| 输入门       | 哪些新信息值得记下来     |
| 输出门       | 此刻需要拿出哪些信息使用 |

这些“门”都是模型学出来的数值计算，并不是人在编写每一条记忆规则。

但 RNN、LSTM 还有一个共同限制：**当前这一步依赖上一步的状态，阅读过程必须按顺序推进。**

于是我们来到 Transformer 的关键思路。

### （5）注意力：处理一个词时，直接联系相关的上下文

回到这句话：

> 小明口渴了，于是他拿起杯子，喝了一口……

处理“他”时，“小明”可能是重要线索；预测“喝了一口”后面的内容时，“口渴”“杯子”等信息可能有帮助。

注意力机制做的事情，可以先理解成：

> **在当前允许查看的上下文中，计算各处信息与当前位置的关联，再按不同权重汇总信息。**

它提供了直接联系远处词元的路径，不必完全依赖信息沿着 RNN 的状态一步步传过来。

这里的“注意力”是一个数学机制，不表示模型具有人类的意识。

教材里最吓人的 Q、K、V，可以用“找资料”来理解：

| 名称     | 类比                   | 作用                |
| -------- | ---------------------- | ------------------- |
| Q，Query | 我正在查什么           | 发起匹配            |
| K，Key   | 每份资料供匹配的标签   | 与 Q 比较，计算分数 |
| V，Value | 每份资料实际提供的内容 | 按权重汇总          |

处理“他”时，可以把它想象成拿着一个查询，去前文寻找相关信息；“小明”的信息可能获得较高权重，被更多地加入“他”的新表示中。

**实际的 Q、K、V 都是从词元表示计算出来的数字向量，不是真正的文字问题和标签。** 这个类比只是帮助你理解三者的分工。

所以，那条注意力公式目前只需要读成：

```text
计算匹配分数 → 转成权重 → 按权重汇总信息
```

其中 Softmax 的作用，是把分数转成总和为 1 的权重。

“自注意力”中的“自”，表示这些查询和资料来自同一条序列内部：句子中的词元彼此交换信息。

“多头注意力”，则是**同时进行多组这样的计算，再把结果合起来**。不同组可以学习不同的关联方式，例如指代、动作与对象的联系等，但并没有人预先规定每个头必须负责哪一类关系。

### （6）Transformer：把注意力和几个配套模块组合起来

注意力是核心，但一个完整的 Transformer 还需要其他组件。你先知道它们各自的工作即可：

| 组件          | 通俗理解                           |
| ------------- | ---------------------------------- |
| 词嵌入        | 把文字转换成数字表示               |
| 位置信息      | 告诉模型这些文字的先后位置         |
| 多头注意力    | 从其他位置汇总相关信息             |
| 前馈网络 FFN  | 对每个位置汇总后的信息继续加工     |
| 残差连接 Add  | 保留原表示，再加上这一步的加工结果 |
| 层归一化 Norm | 调整数值尺度，帮助训练更稳定       |

为什么需要位置信息？看这两句话：

> 小明追小狗。
> 小狗追小明。

词一样，顺序改变，意思就变了。模型需要获得顺序信息，才能更好地区分它们。教材里的正弦、余弦公式，是提供位置信息的一种具体方法，第一遍不用记。

这些处理模块还会堆叠多层，让每个位置的表示经过反复加工。

教材先介绍的是用于翻译的 **Encoder–Decoder** 结构：

```text
英文句子 → Encoder 编码器 → 输入句子的表示
                                  ↓ 供参考
已生成的中文 → Decoder 解码器 → 下一个中文 token
```

编码器负责把输入加工成便于使用的表示；解码器参考这些表示和已经生成的文字，继续输出。

这里有两种“查看资料”的方式：

- 解码器查看自己已有的文字：自注意力。
- 解码器查看编码器提供的输入表示：交叉注意力。

另外，教材说 Transformer 便于并行计算，**主要是说训练时可以同时计算多个位置，不需要像 RNN 那样逐步传递隐藏状态**。这不意味着生成回答时，所有未来文字都能一次确定。

### （7）Decoder-Only：把“根据已有内容继续生成”作为统一方式

3.1.3 接着介绍：可以不再设置一套独立的编码器，而采用只有解码器式模块的结构，处理输入并续写。

这里也去掉了原来用于读取独立编码器输出的交叉注意力，保留因果自注意力、前馈网络等核心组件。

它的生成过程可以示意为：

```text
输入：小明口渴了
生成：于是

已有内容：小明口渴了，于是
继续生成：他

已有内容：小明口渴了，于是他
继续生成：……
```

这就叫**自回归**：每次生成的新内容，都会成为后续生成所依据的内容。

模型给出的是下一个 token 的概率分布，再由生成策略选择 token，未必每次都选概率最高的那个。

那“回答问题”怎么也能算续写呢？

因为输入可以组织为：

```text
用户：为什么口渴时要喝水？
助手：
```

模型接下来生成助手应答的内容。通过预训练和后续训练，它逐渐学会语言规律、知识关联以及按要求回答等行为。

**没有独立的 Encoder，也不等于不处理或不理解输入。** 输入仍然会经过多层计算，影响后面的输出。

还有最后一个概念：**因果掩码，也就是“不许偷看后面的答案”。**

训练材料可能是完整句子，但训练“根据‘小明’预测后文”时，不能让这个位置提前看到后面的答案。因此，模型会屏蔽当前位置之后的信息。

你可以把它想成：同一页上放了很多道练习题，每道题都有自己的挡板，只允许看它应当使用的前文。这样可以并行训练多个位置，同时遵守“根据已有内容预测后文”的规则。

### （8）现在回看 3.1，你可以这样把它串起来

| 方法                 | 核心办法                             | 推动下一步改进的问题或特点           |
| -------------------- | ------------------------------------ | ------------------------------------ |
| N-gram               | 统计固定长度词组的出现频率           | 没见过的组合难处理，利用的上下文有限 |
| 早期神经网络语言模型 | 用词向量和神经网络学习规律           | 这里介绍的模型仍只看固定数量的前文   |
| RNN / LSTM           | 逐词处理，把信息保存在状态里         | 远处信息难传递，顺序计算限制并行     |
| Transformer          | 用注意力联系上下文，反复加工表示     | 提供了更适合大规模训练的结构         |
| Decoder-Only         | 利用因果注意力，不断预测下一个 token | 形成适合文本生成的统一方式           |

你现在可以试着用自己的话解释三个问题：

1. **为什么要有词向量？**——把文字变成模型能计算、能学习其关系的数字表示。
2. **注意力在做什么？**——计算当前位置与上下文的关联，按权重汇总信息。
3. **模型怎么生成一段话？**——预测并选出下一个 token，把它接上，再继续预测。

能解释到这个程度，你就已经建立了阅读 3.1 所需的整体认识。接下来再看教材时，每遇到一个公式或类名，先把它放回这条流程中，辨认它负责哪一步。

## 2. Transformer 如何实现并行？

**问：Transformer 如何实现并行的？这点不太懂，你再结合例子解释一下。**

**答：** 关键是：**Transformer 可以同时处理一段已知文本里的多个位置。训练时，这让它能同时练习预测多个位置的下一个词。**

但生成回答时，后面的内容还没产生，通常仍然要逐个 token 生成。

我们用一个例子，把这两件事分开看。为方便理解，假设下面每个词都是一个 token：

> 小明 / 拿起 / 杯子 / 喝水

### （1）RNN 为什么需要排队？

RNN 每处理一个词，都要使用上一步更新后的“笔记”，也就是隐藏状态：

```text
“小明” + 初始笔记 → 笔记①
“拿起” + 笔记①   → 笔记②
“杯子” + 笔记②   → 笔记③
“喝水” + 笔记③   → 笔记④
```

这里存在硬性的依赖关系：

- “拿起”要等笔记①出来，才能处理。
- “杯子”要等笔记②出来，才能处理。
- “喝水”要等笔记③出来，才能处理。

**即使有四个计算单元，也没法直接把这四步同时做完，因为后一步需要的输入还没有算出来。**

就像接力赛：下一棒必须等上一棒交接。

### （2）Transformer 改变了什么？

Transformer 在同一层里，处理各个位置时，使用的是**这一层开始时就已经准备好的输入表示**。

假设四个词的输入表示是：

```text
小明 → x₁
拿起 → x₂
杯子 → x₃
喝水 → x₄
```

这四串数字一开始都已经有了。

于是，各个位置可以同时开始计算自己的 Q、K、V：

```text
x₁ → Q₁、K₁、V₁  ┐
x₂ → Q₂、K₂、V₂  │
x₃ → Q₃、K₃、V₃  ├─ 可以同时计算
x₄ → Q₄、K₄、V₄  ┘
```

接下来，各个位置也可以同时计算注意力。

以生成模型中的因果自注意力为例：

| 正在处理的位置 | 可以利用的本层输入信息 |
| -------------- | ---------------------- |
| 小明           | 小明                   |
| 拿起           | 小明、拿起             |
| 杯子           | 小明、拿起、杯子       |
| 喝水           | 小明、拿起、杯子、喝水 |

你可能会想：

> “杯子”要参考“小明”和“拿起”，那不还是得等它们？

**不用等它们在这一层的新结果。它参考的是它们进入这一层时的表示，这些表示已经准备好了。**

这是两种结构最关键的区别：

```text
RNN：
后一个位置，依赖前一个位置刚算出的新状态。

Transformer：
各个位置，读取这一层已经备齐的输入表示，分别算新结果。
```

可以想象四名学生同时拿到同一份资料，各自完成一道题。他们需要阅读资料，但不需要等前一名学生答完，才能开始答自己的题。

### （3）注意力公式怎样把这些计算一起做？

教材里那部分 `QKᵀ`，可以先理解成“一次列出所有位置之间的匹配分数”：

| 查询来自 ↓ / 匹配对象 → | 小明 | 拿起 | 杯子 | 喝水 |
| ------------------------- | ---: | ---: | ---: | ---: |
| 小明                      | 分数 | 屏蔽 | 屏蔽 | 屏蔽 |
| 拿起                      | 分数 | 分数 | 屏蔽 | 屏蔽 |
| 杯子                      | 分数 | 分数 | 分数 | 屏蔽 |
| 喝水                      | 分数 | 分数 | 分数 | 分数 |

上表展示的是加入因果掩码后的可用分数；`QKᵀ` 本身负责计算匹配分数，屏蔽未来位置由掩码完成。

每一行对应一个位置的注意力计算。

**计算第三行，不需要先得到第二行的答案。** 所以可以把它们组织成矩阵运算，交给 GPU 并行处理。

后续把分数转成权重、按权重汇总 V，也可以同时处理多个位置。前馈网络对各个位置的加工，同样可以并行。

不过，**层与层之间仍有先后顺序**：第二层需要第一层的输出。这里说的并行，主要是同一层内多个位置的并行。

### （4）为什么训练能并行，生成却通常还要一个个来？

因为训练时，完整的训练句子已经在手里，可以同时安排多道预测题：

| 训练题 | 允许参考的内容   | 要预测的答案 |
| ------ | ---------------- | ------------ |
| ①     | 小明             | 拿起         |
| ②     | 小明、拿起       | 杯子         |
| ③     | 小明、拿起、杯子 | 喝水         |

这三道题可以在一次前向计算中一起处理，再把各位置的预测与正确答案比较，用于训练。

**因果掩码负责防止作弊**：做第一题的位置看不到“拿起”；做第二题的位置看不到“杯子”。所有题同时做，不代表每道题都能看见整句答案。

但实际生成时，情况是：

```text
输入“小明”
    ↓
先生成“拿起”
    ↓
才能根据“小明 拿起”生成“杯子”
    ↓
才能继续生成“喝水”
```

“拿起”还没选出来时，下一步究竟该用什么输入还不知道，因此标准自回归生成通常必须逐步推进。

已经给定的提示词可以并行处理，每次生成内部的大量计算也可以并行；**尚未生成的未来 token，则仍存在前后依赖。**

你可以用一句话检验自己有没有抓住区别：

> **Transformer 处理“杯子”时，是否必须等“拿起”在同一层算出新表示？**

答案是“不必”，因为它读取的是已经备齐的本层输入。这就是它能在位置之间并行计算的关键。

## 3. 采样参数中提到的 Softmax，就是图 3.2 中的 Softmax 吗？

**问：《第三章 大语言模型基础》3.2.1 节的“（1）模型采样参数”中提到的 Softmax，与图 3.2“神经网络语言模型架构示意图”中的 Softmax 是同一种运算吗？它们有什么联系？**

**答：是的，是同一种 Softmax 运算，而且这两处的作用一致：把模型给各个候选词的“分数”，转换成“概率”。**

图 3.2 展示了它在模型中的位置：

```text
输入前面的词
    ↓
神经网络计算
    ↓
得到各个候选词的分数（叫 logits）
    ↓
Softmax：把分数转成概率
    ↓
根据概率选择下一个词
```

例如，输入“我口渴了，想喝”，假设只有三个候选词：

| 候选词 | 模型算出的分数 | 经过 Softmax 后的概率 |
| --- | ---: | ---: |
| 水 | 3 | 约 66.5% |
| 茶 | 2 | 约 24.5% |
| 果汁 | 1 | 约 9.0% |

这些分数本身不是概率，经过 Softmax 后，各项都在 0～1 之间，加起来等于 1。**Softmax 负责算概率，之后的选择策略才负责决定输出哪个词。** 图 3.2 把这部分流程简化画在了一起。

**3.2.1（1）是在这个基础上，进一步讲如何调整输出概率。** 其中 Temperature 的做法是：先把分数除以温度 $T$，再交给 Softmax。

仍用上面的分数举例：

| 温度 | 送进 Softmax 的分数 | 水 / 茶 / 果汁的概率 |
| --- | --- | --- |
| $T=0.5$ | 6、4、2 | 约 86.7% / 11.7% / 1.6% |
| $T=1$ | 3、2、1 | 约 66.5% / 24.5% / 9.0% |
| $T=2$ | 1.5、1、0.5 | 约 50.6% / 30.7% / 18.6% |

可以看到：温度低，概率更集中到原本分数最高的候选词；温度高，其他候选词被选中的机会增加。**这调整的是选择的随机性，不保证低温度的答案就更符合事实。**

另外，3.1 节的**注意力公式**中也出现过 Softmax。它还是同一种数学运算，只是处理对象不同：

- **图 3.2 和这里的输出 Softmax**：把候选词的分数变成“下一个词的概率”。
- **注意力中的 Softmax**：把位置之间的匹配分数变成“汇总各处信息的权重”。

## 4. 为什么“提示工程”中介绍 Temperature、Top-k、Top-p 等采样参数？

**问：《第三章 大语言模型基础》的 3.2.1 节标题是“提示工程”，但其中“（1）模型采样参数”却介绍了 Temperature、Top-k、Top-p。我的理解是，这些参数针对的是 LLM，而提示工程属于 LLM 上层的 Agent 层面，似乎不应该在这里讨论模型参数。是教材的分类不够清楚，还是我对提示工程、Agent 和 LLM 之间的关系理解有误？**

**答：你的疑问有道理：Temperature、Top-k、Top-p 确实属于模型生成时的采样参数，严格来说不属于“提示词怎么写”。教材把它们放在“提示工程”下面，是把相关的模型使用方法放在一起讲，分类不够严谨。**

不过，你的理解中有一点需要调整：**提示工程不等于 Agent 层。** 我们分开来看。

### （1）提示词和采样参数，是控制一次模型调用的两类不同输入

例如，你希望模型写一篇故事：

| 类型 | 例子 | 控制什么 |
| --- | --- | --- |
| 提示词 | “请写一个发生在太空的故事，主角是一只猫，限 300 字。” | 任务、内容、要求和输出形式 |
| 采样参数 | Temperature、Top-k、Top-p | 模型生成文字时，如何从候选 token 中选择 |

可以把一次生成理解成：

```text
提示词
  ↓
模型结合上下文，算出下一个 token 的分数
  ↓
根据 Temperature、Top-k、Top-p 等配置调整候选分布
  ↓
选择下一个 token
  ↓
继续生成
```

所以，你说“这些参数是针对 LLM 的”，这个判断是对的。**它们配置的是生成过程，并不是提示词中的文字。**

同时注意，“模型参数”这个说法容易混淆：

- **模型权重**：训练学到的内部数值。
- **这里的采样参数**：调用模型时使用的生成配置。

修改 Temperature 不会重新训练模型，也不会修改模型权重。

### （2）提示工程并不专属于 Agent

即使没有 Agent，你直接向一个模型输入：

> 请把下面这段话总结成三条要点。

你也已经在设计提示词了。

Agent 程序则可能把多种东西组合起来：

```text
Agent 程序
  ├─ 组织提示词：任务、历史对话、工具结果等
  ├─ 设置模型调用配置：包括支持的采样参数
  ├─ 调用模型并处理输出
  └─ 执行工具、更新状态、决定是否继续
```

因此，**提示词和采样配置都可以由 Agent 程序管理，但它们也都可以用于普通的模型调用。** 不能用“提示词属于 Agent、采样参数属于 LLM”把两者划成互不相关的层级。

### （3）为什么教材把它们放在一起？

从这段内容的安排看，我的理解是：作者在介绍“怎样让模型按需求输出”，因此把两种手段合在一起讲：

- 通过提示词表达任务要求。
- 通过采样配置调节生成时的选择方式。

这种安排在实践上有关联，但**“都能影响输出”不代表“都属于狭义的提示工程”**。

更清楚的目录可以是：

```text
3.2 与大语言模型交互
    ├─ 模型生成与采样参数
    │   └─ Temperature、Top-k、Top-p
    └─ 提示工程
        └─ 指令、示例、上下文、输出格式等
```

你阅读时可以直接把 **3.2.1（1）单独理解成“模型调用的生成配置”**，从后面的零样本、单样本和少样本提示开始，再回到“如何设计提示词”这个主题。你发现的是教材分类上的含混，不是自己把这些概念完全理解错了。

## 5. 为何需要分词？按词、按字符和按子词分词有什么区别？

**问：能否结合具体例子，解释《第三章 大语言模型基础》3.2.2.1“为何需要分词”？按词、按字符和按子词分词分别是怎么做的，为什么要采用子词分词？**

**答：**3.2.2.1“为何需要分词”，主要在解释两个问题：

**文字进入模型前，应该切成多大的单位？为什么既不全部按完整单词切，也不全部按单个字符切？**

我们用 `look`、`looks`、`looking`、`looked` 来理解。下面的切分和编号都是教学示例，不代表某个真实分词器的结果。

### （1）先理解“分词器”和“词表”是什么

模型处理文字时，需要先把文字转换成数字。可以把分词器想成一个“切分文字并查编号”的工具，词表就是它使用的编号表。

假设词表中有：

| 文字片段 | 编号（Token ID） |
| --- | ---: |
| `look` | 31 |
| `ing` | 52 |
| `ed` | 76 |
| `cat` | 18 |

那么：

```text
原始文字：looking
    ↓ 切分
文字片段：["look", "ing"]
    ↓ 查词表中的编号
Token ID：[31, 52]
```

这里的 `"look"` 和 `"ing"` 各是一个 token。

注意：**编号只是身份标识。** 31 和 52 相差多少，并不表示它们的意思相差多少。之后，模型还会通过前面学过的 Embedding，把编号转换成用于计算的向量：

```text
文字 → 切分成 token → token 编号 → 向量 → 模型后续计算
```

但这里还有一个问题：为什么要把 `looking` 拆开？直接给整个单词一个编号不行吗？

### （2）方法一：每个完整单词一个编号

当然可以。这就是“按词分词”的基本思路。

例如：

```text
look    → 101
looks   → 102
looking → 103
looked  → 104
```

它很直观：一个单词就是一个 token。

但假设你还要支持：

```text
play、plays、playing、played
work、works、working、worked
……
```

就需要收录很多独立条目。再考虑人名、地名、专业术语、拼写变体和新造词，词表会越来越大。

更麻烦的是，**事先准备好的词表，很难收录以后可能遇到的所有完整单词。**

例如，用户输入一个新名字：

```text
DatawhaleAgent
```

如果词表里没有它，最简单的整词分词器可能只能把它转换成：

```text
[UNK]
```

`UNK` 表示“未知词”。这样，具体拼写信息就丢失了。这就是教材说的 **OOV：词表之外的词，也叫未登录词**。

另外，`look` 和 `looking` 使用两个独立编号，本身没有体现两者共享 `look` 这部分结构。

不过，教材这里可以理解得更准确些：**这不意味着模型绝对学不会它们的关系，而是这种切分方式没有直接提供共享片段，需要模型从训练数据中另外学习。**

### （3）方法二：干脆拆成单个字符

既然完整单词太多，那就只准备字母等基本字符：

```text
looking → ["l", "o", "o", "k", "i", "n", "g"]
```

这样，即使没见过 `looking` 这个完整单词，只要词表包含这些字符，就仍然能表示它。

新名字也能拆：

```text
DatawhaleAgent
→ ["D", "a", "t", "a", "w", "h", "a", "l", "e", "A", "g", "e", "n", "t"]
```

优点是：**可以用较少的基本单位，组合出大量不同的词。**

但代价也很明显：

- **序列变长。** `looking` 原本一个 token 就能表示，现在需要七个。
- **模型需要从更细碎的信息中学习规律。** 它得学会这些字符组合起来有什么含义，而不是直接处理 `look` 这样的较大片段。

比如读中文：

> 我喜欢机器学习。

如果你已经把“机器学习”看成一个熟悉的概念，阅读就比较顺畅；如果只能逐字接收信息，还需要把这些字组合起来理解。这个类比能帮助你体会切得太碎带来的额外负担。

教材说字符分词“不存在 OOV”，也有一个前提：**输入字符都被词表覆盖。** 如果出现未收录的字符，仍然需要其他处理方式。

### （4）方法三：子词分词，让常见片段保留下来

子词分词采用一种折中方式：

> **常见的完整词可以作为一个 token；其他词可以由较小的、可复用的片段组成。**

例如：

```text
look    → ["look"]
looks   → ["look", "s"]
looking → ["look", "ing"]
looked  → ["look", "ed"]
```

同样的片段还可以被其他词复用：

```text
playing → ["play", "ing"]
working → ["work", "ing"]
```

这样做有几个好处：

- 不必给每个完整单词及其各种变形都设置独立条目。
- 不必把所有词都拆成单个字符，序列可以更短。
- 即使一个完整词没见过，也有机会用已有片段表示出来。
- 不同词可以共享片段，给模型学习它们之间的联系提供帮助。

但要注意：**子词不一定是语言学上有明确含义的“词根、词缀”。** 实际切分取决于分词算法和词表，有时切出来的片段在人看来并不自然。上面的 `look + ing` 是方便理解的例子。

### （5）三种方法放在一起看

| 方法 | `looking` 的示意切分 | 主要取舍 |
| --- | --- | --- |
| 按词 | `["looking"]` | 序列短，但需要收录大量完整词，容易遇到词表外的词 |
| 按字符 | `["l","o","o","k","i","n","g"]` | 基本单位可复用，但序列长、信息细碎 |
| 按子词 | `["look","ing"]` | 在词表大小、序列长度和片段复用之间取得折中 |

所以，这一小节你最需要理解的是：**token 的大小可以不同。它既可以是一个完整单词，也可以是单词的一部分；分词器的任务，就是按照既定规则，把输入文字变成模型可以使用的 token 序列。**

下一小节的 BPE，接着回答的就是：**这些可以复用的片段，具体怎么从文本中找出来？**

## 6. 模型调用示例中的 `system` 和 `user` 是什么？为什么要区分？

**问：《第三章 大语言模型基础》3.2.3 节的示例中，为什么消息列表里有 `system` 和 `user` 两种角色？它们分别起什么作用？**

```python
messages = [
    {"role": "system", "content": "You are a helpful assistant."},
    {"role": "user", "content": "你好，请介绍你自己。"}
]
```

**答：**这里的 `system` 和 `user` 是消息的**角色标签**，用来告诉模型：**这段话属于哪一类消息，应该怎样使用它。** `role` 表示消息角色，`content` 是具体的消息内容。

你可以把 `messages` 理解成一份“带身份标记的对话记录”，而不是一段没有区分来源的文字。

### （1）`system`：设置整体行为要求

```python
{"role": "system", "content": "You are a helpful assistant."}
```

意思是：

> 你是一名乐于助人的助手。

这通常是应用开发者设置的整体要求，用于规定模型的身份、回答风格或行为要求。也可以写得更具体：

```python
{"role": "system", "content": "你是一名 Python 老师，请用适合初学者的语言解释，并给出简单例子。"}
```

**这是一段提示词，不是在修改模型权重，也不会凭空赋予模型新的能力。**

### （2）`user`：提出本次具体问题或任务

```python
{"role": "user", "content": "你好，请介绍你自己。"}
```

这是用户本次提出的问题。把两条消息放在一起，可以这样理解：

```text
整体要求：你是一名乐于助人的助手。
本次问题：你好，请介绍你自己。
                     ↓
模型结合这两部分生成回答。
```

如果换成教学场景：

```python
messages = [
    {"role": "system", "content": "你是一名 Python 老师，请用初学者能理解的语言回答。"},
    {"role": "user", "content": "什么是列表？"}
]
```

模型就会在“面向初学者的 Python 老师”这个要求下，回答“什么是列表”。

### （3）为什么要区分这两个角色？

把要求和问题写成一段普通提示词，也可以表达类似意思，但**角色标签让消息的用途更明确**：

| 角色 | 主要用途 | 例子 |
| --- | --- | --- |
| `system` | 设置整体行为要求 | “请用初学者能理解的语言回答。” |
| `user` | 提出当前问题或任务 | “什么是列表？” |

所以，这段代码里的 `system` 和 `user`，是在为模型区分“整体要求”和“当前问题”；它们也是提示词组织方式的一部分。

## 7. 如何理解 3.3.1 的缩放法则、资源配比和能力涌现？

**问：《第三章 大语言模型基础》3.3.1“缩放法则”不太容易理解。能否结合例子，解释缩放法则、模型大小与训练数据的配比，以及这一节提到的“能力涌现”？**

**答：**3.3.1“缩放法则”讨论的是：**训练大模型时，如果投入更多资源，模型会怎样变好？预算有限时，这些资源又该怎么分配？**

这一节可以拆成三部分理解：**扩大规模的规律、资源如何搭配、能力涌现。** 我们逐个看。

### （1）先区分三个容易混淆的量

| 教材中的概念 | 是什么意思 | 可以怎样理解 |
| --- | --- | --- |
| 模型参数量 | 模型内部可学习的数值有多少 | 模型有多少可调整的“旋钮” |
| 训练数据量 | 训练过程中使用多少文本 token | 给模型多少学习材料 |
| 训练计算量 | 训练时进行了多少计算 | 为学习过程投入多少计算工作 |

这里的“参数”是前面讲过的**模型权重**，不是 Temperature、Top-k 这些生成配置。

例如，你要训练一个能续写句子的模型：

```text
学习材料：小明口渴了，于是喝了一杯水。
                     ↓
让模型预测下一个 token
                     ↓
对照正确答案，计算预测有多不好
                     ↓
调整模型内部参数
                     ↓
不断重复
```

更大的模型，每次计算通常更贵；处理更多训练材料，也需要更多计算。因此，这三个量相互关联，不能随意同时增加而不付出成本。

### （2）“缩放法则”：扩大投入后，进步有一定的规律

假设你想知道：

> 模型规模和训练投入扩大以后，它预测下一个 token 的能力，会不会更好？大概能好多少？

研究者训练了不同规模的模型，发现：**在一定实验范围和条件下，模型的预测损失与参数量、数据量、训练计算量之间，呈现可以用数学关系近似描述的变化趋势。** 这就是这里所说的缩放法则。[原始研究](https://arxiv.org/abs/2001.08361)

先理解“损失 Loss”。

假设训练文本的下一个词确实是“水”：

- 模型给“水”的概率只有 1%，这次预测的损失就比较大。
- 模型给“水”的概率是 80%，这次预测的损失就比较小。

在大量文本上进行评估，可以得到平均损失。**损失下降，表示模型整体上更善于预测这些文本，并不等于所有实际任务都一定做得更好。**

教材提到“幂律”“对数坐标”，你暂时可以用下面这组**虚构数字**体会：

| 训练投入 | 假设的预测损失 |
| --- | ---: |
| 1 份 | 4 |
| 4 份 | 2 |
| 16 份 | 1 |

这里每投入到原来的 4 倍，损失降到原来的一半。这种“按倍数扩大投入，结果也按某种比例变化”的关系，就是幂律的直观例子。

它还有一个含义：**继续进步可能需要越来越大的绝对投入。** 从损失 4 降到 2，只增加了 3 份投入；从 2 降到 1，却增加了 12 份。

实际模型的关系没有这个示例那么简单，但你不必现在就推导公式。

教材说“不会出现明显的瓶颈”，读的时候要加上条件：**这是一定范围内观察到的经验规律，不能理解为无限增加资源，就一定能无限进步。**

### （3）Chinchilla：预算固定时，不能只追求模型大

前面讨论的是“扩大投入会怎样”。这里进一步问：

> 总预算已经固定了，我应该训练一个很大的模型，还是让一个较小的模型学习更多材料？

可以把模型比作一套可以调节的复杂设备：

- 模型越大，可调整的部分越多。
- 但要把这些部分调整好，也需要足够的训练。
- 如果预算大量花在“大设备每运行一次都很贵”上，能练习的次数和材料量就可能受到限制。

于是，可能出现这样的情况：

| 方案 | 模型大小 | 训练材料 | 可能的问题或结果 |
| --- | --- | --- | --- |
| A | 很大 | 相对不足 | 模型没有得到充分训练 |
| B | 较小 | 更充足 | 在同样计算预算下，可能表现更好 |

**Chinchilla 研究的核心，就是寻找给定训练计算预算下，模型大小与训练数据量的合适配比。**

原论文中的一个对比是：Chinchilla 有 700 亿参数，Gopher 有 2800 亿参数；Chinchilla 使用约 4 倍训练数据，在相同训练计算预算下，在论文评测的多项任务上表现更好。[Chinchilla 研究](https://arxiv.org/abs/2203.15556)

所以，你可以把这段理解为：

> **模型的容量和训练量要配合。参数更多，不自动等于效果更好。**

这也不代表“模型越小越好”。这里研究的是如何分配预算，而不是给大小模型排一个永远不变的名次。

### （4）“能力涌现”：为什么看起来会突然会做某件事？

教材最后一段想表达的是：

> 模型发展到一定程度后，在某些任务上，可能从“几乎做不对”变成“开始能做对”，看起来像突然出现了一种能力。

用一个教学类比：你学习编程时，逐渐掌握了变量、循环、函数。这些知识是一点点积累的，但某一天，你终于能独立写出一个完整小游戏。

从“能不能独立写出游戏”这个标准看，你似乎突然跨过了一个门槛。

不过，**不能据此认为模型内部一定发生了某种突然的“觉醒”**。评测方式也会影响我们看到的现象。

例如，一个任务要求连续完成十个步骤，只有全部正确才算成功。即使每个步骤的能力一直在逐渐提高，整体成绩也可能在一段时间内很低，之后才明显上升。有研究指出，部分看似突然的能力涌现，与评测指标的选择有关。[相关研究](https://arxiv.org/abs/2304.15004)

因此，教材中“参数达到数百亿甚至千亿后才出现这些能力”的表述，**不适合当作所有模型通用的固定门槛**。也不能只看参数量，就判断一个模型是否能完成规划、推理或代码任务。

对你现在学习 Agent 来说，这一节需要带走的认识是：

- **模型能力与训练投入有关，但扩大规模需要合理搭配资源。**
- **参数量只是一个信息，实际任务表现更直接。**
- **你调用现成模型时，调整提示词或 Temperature，不是在扩大模型参数量，也不是在重新训练模型。**

目前理解这些，就可以继续学习 3.3.2“模型幻觉”，不必先掌握幂律公式和模型训练预算的计算方法。

## 8. 缩放法则中所说的“模型大小”具体指什么？

**问：在解释 Chinchilla 和训练预算分配时，提到了“更大的模型”和“较小的模型”。这里的“模型大小”应该如何理解？它与模型参数量、训练成本有什么关系？**

**答：**这里的**“模型大小”，主要指模型的参数量，也就是模型内部有多少个通过训练学到的数值。**

可以先从一个非常简单的计算式理解：

$$
y = ax + b
$$

这里：

- $x$ 是输入。
- $y$ 是计算结果。
- $a$、$b$ 是可以通过训练调整的数值，也就是**参数**。

这个简单模型只有 **2 个参数**。训练的过程，就是根据例子不断调整 $a$ 和 $b$，让计算结果更符合要求。

**大语言模型的原理复杂得多，但“参数”的含义是类似的。**

你前面学过的词嵌入、注意力、前馈网络，内部都有大量可学习的数值。例如：

```text
词嵌入：每个 token 对应的向量中，有许多数值。
注意力：把输入变成 Q、K、V 的矩阵中，有许多数值。
前馈网络：用于加工信息的矩阵中，也有许多数值。
```

把这些可学习的数值统计起来，就是模型的参数量。比如，一个有 100 行、200 列的权重矩阵，就包含：

$$
100 \times 200 = 20\,000 \text{ 个参数}
$$

模型中有很多这样的矩阵，而且会堆叠很多层，参数总量就可能达到几十亿、几百亿。

**所以，模型名称里的这些数字可以这样读：**

| 标注 | 参数量 |
| --- | ---: |
| 0.5B | 5 亿 |
| 7B | 70 亿 |
| 70B | 700 亿 |

`B` 表示 billion，即十亿。**70B 模型，就是内部有大约 700 亿个可学习参数。** 它不表示看过 700 亿篇文章，也不表示存着 700 亿条知识。

再回到训练预算分配的问题：

> 在同样训练预算下，选择更大的模型，还是让较小的模型学习更多材料？

假设有两个结构相近的模型：

- **模型 A：70 亿个参数。**
- **模型 B：700 亿个参数。**

模型 B 内部需要参与计算、在训练中调整的数值更多，因此处理相同一批训练材料时，通常需要更多计算。

预算固定时，就可能出现：

```text
选择更大的模型
    → 每处理一批材料更贵
    → 能负担的训练材料量受到限制

选择较小的模型
    → 每处理一批材料更便宜
    → 可以把更多预算用于学习更多材料
```

这就是前面说的“模型大小与训练量需要配合”。

你可以把**参数量理解成模型可用于学习和表达规律的容量规模**，但它不是“聪明程度”的直接分数。参数多的模型如果训练不足，也可能不如参数较少、训练更充分的模型。
