# 第一章学习疑惑与解答

本文件整理阅读[第一章 初识智能体](<../../hello-agents/docs/chapter1/第一章 初识智能体.md>)时的疑惑及讨论结果。

## 1. 如何理解“基于模型的反射智能体”？

对应教材：**1.1.1 传统视角下的智能体**，关于基于模型的反射智能体、内部世界模型和前车暂时无法被感知的段落。

### 疑惑

- “反射”是什么意思？为什么有模型、有记忆的智能体仍然叫“反射智能体”？
- “无法被直接感知”是什么意思？
- 既然智能体还维持着对前车存在、速度和位置的判断，为什么又说它无法感知前车？

### 解答

**（1）“反射”指按照“条件 → 动作”的规则做出反应。**

例如：如果前方有车辆，而且距离过近，就减速。

“反射”强调的是行动如何被选择：满足某个条件，就执行对应动作，不需要先搜索、比较许多未来的行动方案。它并不意味着智能体不能有模型或记忆。

两类反射智能体的区别，在于它们根据什么判断条件是否满足：

| 类型                 | 判断依据                                       | 决策过程                               |
| -------------------- | ---------------------------------------------- | -------------------------------------- |
| 简单反射智能体       | 当前的感知输入                                 | 当前感知 → 条件—动作规则 → 行动     |
| 基于模型的反射智能体 | 根据当前感知、历史信息和世界模型更新的内部状态 | 更新内部状态 → 条件—动作规则 → 行动 |

因此，基于模型的反射智能体仍然通过规则选择行动；模型和记忆帮助它更好地判断当前情况。

**（2）“无法被直接感知”指当前观测没有提供相关信息，或不足以确定相关状态。**

传感器获得的观测只是环境的一部分，不一定覆盖完整的环境状态。当前观测不到某个对象，不代表过去从未观测过，也不代表完全无法推测它的状态。

把前车的例子按时间展开：

1. **刚才看得见前车**：系统从连续观测中估计出前车的位置和速度。
2. **现在前车被遮挡了**：相关传感器暂时没有提供前车的新观测，系统无法直接确定它此刻的位置和速度。
3. **系统保留此前的信息**：前车刚才在哪里、以什么速度运动，并不会因为当前看不见而从内部状态中消失。
4. **利用世界模型更新估计**：结合此前的位置、速度和经过的时间，系统可以推测前车现在大概在哪里。例如，在暂时假设前车保持原速度的情况下，估计它向前移动了多远。

**“当前直接观测到了什么”与“根据过去的信息估计现在是什么情况”，是两回事。**教材说“维持判断”，指的是维持并更新一个估计，不是说系统仍然直接测到了前车的当前状态。

**（3）内部状态与世界模型承担不同的作用。**

- **内部状态**：保存对当前环境的估计，例如“前车可能在什么位置、速度大概是多少”。它会结合历史观测、先前行动和新观测持续更新。
- **世界模型**：描述环境如何变化，以及智能体的行动如何影响环境，例如“车辆的位置如何随速度和时间变化”。

可以把它们的关系理解为：

```text
此前的内部状态 + 当前观测 + 先前行动 + 世界模型
                         ↓
                 更新后的内部状态
                         ↓
                   条件—动作规则
                         ↓
                       行动
```

**（4）估计带有不确定性，需要新观测来修正。**

前车可能在遮挡期间减速、变道或停下，因此“保持原速度”只是用于估计的假设。缺少新观测的时间越久、期间可能发生的变化越多，估计通常就越不可靠。重新观测到前车后，系统应据此修正内部状态。

教材用“隧道”举例略显含糊：进入隧道并不必然看不见前车。应把这个例子理解为“由于遮挡或其他原因，相关传感器暂时没有提供前车的新观测”。

### 帮助理解的类比

你看见一个人走到墙后面：现在你看不见他，但不会因此认为他消失了。你可以根据他刚才的位置、方向和速度推测他现在大概在哪里；不过，他也可能在墙后停下来，所以推测不等于直接看见，也不保证正确。


## 2. 如何理解“亚符号主义 AI”？

对应教材：**1.1.3 智能体的类型**，基于知识表示的分类中，关于亚符号主义（连接主义）的段落。

### 疑惑

- 亚符号主义 AI 是不是类似于图形匹配、函数匹配？
- 能否用一个具体例子说明，它如何学习和表示知识？

### 解答

**（1）图形匹配、函数拟合与亚符号主义讨论的是不同层面。**

| 概念           | 关注的问题                         | 例子                                   |
| -------------- | ---------------------------------- | -------------------------------------- |
| 图形识别或匹配 | 系统要完成什么任务？               | 判断一张手写数字图片是不是 8           |
| 函数拟合       | 如何从样本中学出输入与输出的关系？ | 学习从图片像素到数字类别的映射         |
| 亚符号主义     | 如何在内部表示和处理知识？         | 通过大量数值参数及网络计算体现识别能力 |

如果“函数匹配”指的是“从样本中拟合出输入与输出的关系”，那么这个理解很接近神经网络的学习方式。不过，函数拟合并不专属于亚符号主义；图形识别也只是它能够完成的一类任务。亚符号主义还可以用于处理声音、文字等数据。

**（2）具体例子：识别手写数字 8。**

假设用显式规则设计一个识别程序，你可能写：

> 如果图形由上下两个封闭的圈组成，就判断它是 8。

这是符号主义思路的简化例子：“圈”“上下”“封闭”都是明确的概念，判断规则也可以直接读出来。这条规则只是帮助理解的示意，并不是可靠的数字识别算法；例如，有人写的 8 没有完全封口，就可能不满足它。

典型的神经网络采用另一种做法：

1. **接收数据**：把图片转换成一串数值，表示每个像素的明暗程度。
2. **通过例子学习**：提供大量手写数字图片及正确标签。网络预测错误时，训练程序调整其中的数值参数，使预测逐渐更准确。
3. **识别新图片**：训练后，给它一张没见过的、写得歪歪扭扭的 8，它也可能识别出来。

从数学上看，可以把这个过程理解为学习一个带参数的函数：

```text
图片像素 x → 神经网络 fθ(x) → 各个数字的预测概率 → 预测的数字
```

其中，θ 代表训练中调整的大量参数。学习的目标是找到合适的参数，使输入图片经过这个函数后，能够得到正确的识别结果。

**（3）关键区别：“怎么认出 8”的知识存在哪里？**

在上述神经网络中，你通常找不到一条直接写着“上下两个圈就是 8”的规则。学习到的识别能力主要分布在大量数值参数中，并通过这些参数共同参与的网络计算体现出来。

单独拿出一个参数，例如 `0.37`，通常无法说它代表“上面的圈”还是“下面的圈”。也不能认为每个神经元都必然对应一个可以明确命名的概念。

教材所说的“亚符号主义”，强调的就是这种通过数值参数及计算活动表示、处理知识的思路。虽然网络最后输出了“8”这个明确的符号，但它内部所学的知识并不是一套可直接阅读的符号规则。

**（4）它不只是把新图片与存储的图片逐张比对。**

在这个例子中，神经网络通过训练学出一个数值映射，再利用这个映射处理新图片。因此，它有可能识别训练时没有见过的写法，而不要求新图片与某张已存储的图片完全一致。

补充参考：[《Deep Learning》第六章：Deep Feedforward Networks](https://www.deeplearningbook.org/contents/mlp.html)，关于神经网络通过学习参数来逼近输入与输出映射的说明。


## 3. “工具”“协作者”与 Workflow、Agent 是什么关系？

对应教材：**1.4.1 作为开发者工具的智能体**、**1.4.2 作为自主协作者的智能体**、**1.4.3 Workflow 和 Agent 的差异**。

### 疑惑

- “工具”“协作者”模式与 Workflow、Agent 有什么关系？是否可以一一对应？
- 为什么教材先介绍“工具”“协作者”模式，再介绍 Workflow、Agent？

### 解答

**（1）它们从两个不同角度描述系统。**

| 教材位置                         | 观察角度           | 核心问题               |
| -------------------------------- | ------------------ | ---------------------- |
| 1.4.1、1.4.2：“工具”“协作者” | 人与 AI 的协作关系 | 人把什么工作交给 AI？  |
| 1.4.3：Workflow、Agent           | 系统内部的运行方式 | 谁决定下一步执行什么？ |

两组概念都涉及自主性，因此有联系，但不能直接理解成“工具＝Workflow，协作者＝Agent”。

**（2）“工具”和“协作者”，主要看人如何使用 AI。**

- **工具模式**：人主导整体工作，AI 辅助完成其中的任务。例如，你自己开发程序，让 AI 解释报错、检查某个函数，再由你推进后续工作。
- **协作者模式**：人委托一个目标，让 AI 负责规划和推进。例如：“把登录失败的问题修好，并验证结果。”具体查哪些文件、如何修改，主要交给它处理。

这里的“工具”指整个 AI 系统在人的工作中扮演的角色，与 `get_weather()` 这种供 AI 调用的工具函数含义不同。

“协作者”也不一定是多个智能体组成的团队。一个能够自主规划、执行和调整行动的智能体，也可以承担协作者角色；教材 1.4.2 介绍的第一种架构就是单智能体自主循环。

**（3）Workflow 和 Agent，主要看系统如何决定执行步骤。**

- **Workflow**：程序预先规定步骤、分支和循环。例如固定执行“读取报错 → 生成补丁 → 运行测试 → 汇报”，以及测试失败时进入哪个预设分支。
- **Agent**：模型根据当前情况决定下一步。例如发现报错信息不足，就先读取相关文件；修复后测试失败，再决定继续检查哪里、尝试什么修复方案。

Workflow 可以调用 LLM，也可以包含分支和循环。即使某一步让 LLM 自由生成内容，整体的步骤编排仍可能由程序预先规定。

Agent 同样需要程序和约束。例如，1.3.3 的代码规定最多循环 5 次，但每轮选择哪个工具、传入什么参数、何时结束，主要由模型决定。因此，区分两者的关键是流程与行动的决定方式，而不是是否存在循环或 `if` 语句。

**（4）两组概念可以组合，但自主协作者通常需要 Agent 的自主决策能力。**

一个被人当作辅助工具使用的系统，内部也可以运行 Agent。例如，你只让它检查一个函数，但它会自主阅读依赖、选择测试并分析结果。对你而言，它在辅助你的开发工作；内部却有自主决策过程。

一个承担协作者角色的系统，也可以结合 Workflow。例如，让 Agent 自主寻找修复方案，同时由固定流程规定“修改完成后必须运行测试，交付前必须经过审核”。这里，Agent 负责在任务中选择行动，Workflow 负责规定必要的阶段和检查步骤。

教材 1.4.2 提到的“组织化工作流”和预设 SOP，也说明协作者系统中可以包含预先编排的流程。不能仅因为一个固定流程能够全自动运行，就认为它具备自主协作者的规划和调整能力。

**（5）可以把章节安排理解为：先讲怎样与 AI 工作，再讲系统怎样推进任务。**

1.4.1、1.4.2 从使用者的角度介绍 AI 在实际工作中扮演的角色；1.4.3 则切换到系统实现的角度，解释任务执行过程如何被组织和控制。这是一种帮助理解教材结构的阅读方式，并不是把前两节的模式分别改名为 Workflow 和 Agent。

补充参考：[Anthropic：Building effective agents](https://www.anthropic.com/engineering/building-effective-agents)，关于预定义工作流、模型动态决定流程和工具使用，以及不同架构模式可以组合的说明。
