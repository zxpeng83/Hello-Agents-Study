# 第十一章学习疑惑与解答

本文件整理阅读[第十一章 Agentic-RL](<../../hello-agents/docs/chapter11/第十一章 Agentic-RL.md>)时的疑惑及讨论结果。

## 1. 第十一章的 Agentic RL 是 LLM 层面的训练，还是 Agent 层面的训练？是否同时训练了两者？

对应教材：**11.1.3 Agentic RL 的核心理念**，以及 **11.3 SFT 训练**、**11.4 GRPO 训练**。

### 疑惑

- 第 11 章提到的 Agentic RL 是 LLM 层面的训练，还是 Agent 层面的训练？
- 是不是涵盖了 LLM 和 Agent 的训练？
- 11.1.3 中提到的推理、工具使用、记忆、规划、自我改进、感知，看着像是 Agent 层面的东西，应该怎样理解？

### 解答

**（1）直接更新的是 LLM 参数，没有两套独立的训练。**

**训练直接更新的是 LLM 参数，希望改变的是 Agent 的行为。** “LLM 层面”和“Agent 层面”在这里描述的是两个不同维度。

第 11 章的实战没有另外一套独立的“Agent 训练”。**训练前后发生变化的是模型参数。**

可以把 Agent 简化理解为：

`Agent = LLM（负责决策）+ 工具 + 记忆 + 执行循环`

| 你关心的问题 | 本章的答案 |
|---|---|
| 训练时具体更新什么？ | LLM 的可训练参数；启用 LoRA 时更新适配器参数 |
| 希望改善什么？ | 推理、选择行动、使用工具、完成任务的能力 |
| 工具代码、工作流、记忆库会自动被训练修改吗？ | 本章的训练没有更新这些部分 |

**（2）训练 LLM，可以改变 Agent 的决策行为。**

教材在 [11.1.3](<../../hello-agents/docs/chapter11/第十一章 Agentic-RL.md>) 中的关键表述是：**“将 LLM 视为一个可学习的策略”**。这里的“策略”就是：给定当前问题、历史和环境反馈，决定下一步做什么。LLM 承担了这个角色，因此训练它就能改变 Agent 的决策行为。

之所以章节叫 **Agentic RL**，是因为它还介绍了一个更大的方向：让 LLM 负责 Agent 的决策，再通过任务反馈训练这个 LLM，改善 Agent 的行为。这时说“训练 Agent”，主要就是在训练它负责决策的“大脑”。

例如，训练一个搜索 Agent，可以让它经历：

> 接收问题 → 决定搜索内容 → 查看结果 → 继续搜索或回答 → 根据任务完成情况获得奖励 → 更新 LLM 参数。

工具负责执行搜索，训练使 LLM 学会更合理地选择搜索时机、查询内容和停止时机。

你可以把本章理解为：**通过训练 Agent 的“决策模型”，提升 Agent 完成任务的能力。**

**（3）这六项能力，分别可以训练 LLM 学会什么？**

**这六项确实是在描述 Agent 层面的能力。**

关键在于：**Agent 的很多行为，是由内部的 LLM 决定的。** 所以，训练 LLM 的决策方式，就能改善对应的 Agent 能力。

| Agent 能力 | 希望模型学会的决策或行为 |
|---|---|
| 推理 | 如何分解问题、推导并得出答案 |
| 工具使用 | 什么时候调用工具、选择哪个工具、填写什么参数 |
| 记忆 | 哪些信息值得保存、什么时候检索、哪些信息应该更新或删除 |
| 规划 | 先做什么、后做什么，遇到失败后怎样调整计划 |
| 自我改进 | 什么时候检查自己的结果、如何发现错误并修正 |
| 感知 | 如何理解环境信息，并据此行动；涉及图像时还需要多模态模型或视觉工具支持 |

这里，“工具使用”“记忆”等描述的是**能力目标**；LLM 参数则是本章讨论的**学习发生的位置**。

**（4）以“记忆”为例，区分记忆设施和管理记忆的决策。**

假设 Agent 有一个保存笔记的工具：

- 工具和数据库负责：把内容存进去、再读出来。
- LLM 负责决定：这条信息要不要记？现在需要查什么？旧信息要不要更新？

如果训练发现“保存用户的关键要求，能提高后续任务成功率”，就可以利用这个反馈更新 LLM，让它以后更倾向于保存这些信息。

**数据库本身没有被训练，但 Agent 管理记忆的行为得到了训练。** 因而，把这个过程称为“训练 Agent 的记忆管理策略”是合理的。

**（5）本章实际案例主要训练数学推理能力，需要区分理论范围和实战范围。**

本章实际做的事情是：

> 拿 Qwen 模型 → 用数学题进行 SFT 和 GRPO 训练 → 得到更擅长解数学题的 Qwen 模型。

**第 11 章的概念范围比实际案例更广。** 它介绍了多步环境交互的 Agentic RL，但配套案例主要是：

> GSM8K 数学题 → 模型生成多个解答 → 按答案正确性等规则打分 → GRPO 更新模型。

所以，读它的代码时，你看到的主要是 **LLM 数学推理的 SFT＋RL 后训练**，尚未完整展示上述多轮工具交互训练。本章使用的 TRL 也正是承担这类模型后训练的库。

- **11.1.3 的理论范围**：介绍如何通过强化学习改善上述六类 Agent 能力。
- **后面的数学题实战**：主要通过 SFT 和 GRPO 训练模型的数学推理，没有逐一实现工具使用、记忆管理等能力的训练。

所以，**不能因为直接更新的是 LLM 参数，就认为它不属于 Agent 能力训练；也不能因为章节介绍了六项能力，就认为后面的数学题案例把六项都训练了。**

补充参考：[TRL 官方说明](https://huggingface.co/docs/trl/quickstart)，关于 SFT、GRPO 等模型后训练方法的说明。


## 2. LoRA 微调调整的是什么？模型参数与 config、内存有什么关系？

对应教材：**11.3.2 LoRA:参数高效微调**，以及 **11.3.3 SFT 训练实战**中关于训练参数和 LoRA 参数的说明。

### 疑惑

- 第 11 章提到的 LoRA 微调，是指对 LLM 参数进行调整吗？
- LLM 参数调整是否和常规程序一样，有个 config 配置文件进行配置调整？
- 文章的意思好像是 LLM 调参与内存有关系，为什么参数调整和内存有关系？

### 解答

**LoRA 属于模型参数训练，但它通常会冻结 LLM 原有的权重，只训练新增的一小部分参数。** 这里的困惑，主要是“参数”这个词在普通程序配置和模型训练中，含义不一样。

**（1）LLM 的“模型参数”，是参与计算的大量数值。**

先看一个非常简单的程序：

```python
def predict(x, w, b):
    return w * x + b
```

这里的 `w` 和 `b` 就可以看成模型参数。它们的值不同，同一个输入得到的结果就不同。

假设我们提供这些训练样本：

```text
输入 1，希望输出 3
输入 2，希望输出 5
输入 3，希望输出 7
```

训练程序可以根据预测误差，反复调整 `w` 和 `b`，让它们逐渐接近：

```text
w = 2
b = 1
```

于是，模型学到了 `y = 2x + 1` 这个关系。**计算代码可以不变，通过改变参与计算的数值，程序的输出就发生了变化。**

LLM 的模型参数也是这样的数值，只是规模巨大，以数组、矩阵等形式参与复杂计算。例如，**0.6B 参数就是大约 6 亿个参数**。这些数值共同影响模型如何处理输入、生成输出。

**（2）config 确实存在，但它通常配置的是“怎样训练”，而非逐个填写模型权重。**

例如，本章这样的配置：

```python
config = {
    "learning_rate": 0.0001,
    "batch_size": 2,
    "lora_r": 8,
}
```

这些配置分别控制训练步长、每批处理多少样本、LoRA 矩阵的大小，通常称为**超参数**。

| 类型 | 例子 | 谁来调整 |
|---|---|---|
| 模型参数 | 模型内部大量的权重数值 | 训练算法根据数据自动调整 |
| 训练配置、超参数 | 学习率、批大小、LoRA 的秩 | 开发者设置，控制训练方式 |

你不会手工打开配置文件，把几亿个权重挨个改好。训练的大致过程是：

> 提供数据 → 模型生成预测 → 计算损失 → 通过反向传播计算梯度 → 优化器更新参数 → 重复。

**只修改 config 而不执行训练，不会让模型权重自动学到新知识。** 优化器才是在训练过程中更新权重的组件。

**（3）参数与内存有关，因为这些数值和训练过程中的数据，都需要存储空间。**

这里的“内存”是**硬件存储空间**。本章使用 GPU 训练时，主要关心的是 **GPU 显存**，与前面讨论的“Agent 记忆库”是不同概念。

仅存放模型参数就需要空间。例如，假设大约 6 亿个参数都使用每个 2 字节的 FP16 格式：

```text
6 亿 × 2 字节 ≈ 1.2 GB
```

**这只是权重本身的大小，还不是训练所需的全部显存。**

训练时还要存储：

| 占用空间的内容 | 用来做什么 |
|---|---|
| 模型权重 | 执行模型计算 |
| 梯度 | 表示损失如何随可训练参数变化，供参数更新使用 |
| 优化器状态 | 记录辅助更新的信息，例如 Adam 保存的历史统计量 |
| 中间计算结果、临时数据 | 支持反向传播等计算 |

所以，训练通常比只加载模型进行推理更占显存；批次大小、输入长度也会影响占用。

**并不是把一个参数从 `0.1` 改成 `0.2`，它就占用更多内存。** 在相同数据类型下，它们占用的空间一样。主要问题是：参数数量巨大，而且训练还需要配套的计算数据。

**（4）LoRA 节省显存，是因为它大幅减少了“需要训练的参数”。**

两种方式可以这样理解：

- **全量微调**：允许更新模型原有的大量权重，需要为这些可训练权重计算梯度、维护优化器状态。
- **LoRA 微调**：保持原有权重不变，加入较小的可训练矩阵，让它们学习对原模型计算的修正。

因此，LoRA 不需要为全部原始权重保存用于更新它们的梯度和优化器状态，这能节省大量训练空间。

但**原模型仍然要参与计算，中间计算结果也仍会占用空间**，所以 LoRA 不意味着整个大模型变成了一个很小的模型。

教材里列出的具体显存需求，需要结合训练配置理解；不能仅根据“模型有多少参数”，就认定训练一定需要固定大小的显存。

补充参考：[Hugging Face：优化器说明](https://huggingface.co/docs/transformers/optimizers)、[GPU 显存构成](https://huggingface.co/docs/transformers/model_memory_anatomy)、[LoRA 原理](https://huggingface.co/docs/peft/main/en/conceptual_guides/lora)。


## 3. LLM 参数只存储在显存吗？训练时如何更新，并保存到磁盘？

对应教材：**11.3.2 LoRA:参数高效微调**、**11.4.3 GRPO 训练过程解析**，以及 **11.6.4 生产部署**中的模型导出示例。

### 疑惑

- LLM 参数只存储在显存吗？会同步到磁盘进行持久化存储吗？
- 是不是因为 LLM 参数量巨大，且要边训练边调整，所以训练时参数都存储在显存中，随时动态调整并反复训练？

### 解答

**参数不只存储在显存中，也会以权重文件的形式保存在磁盘上。** “在显存中反复计算、更新参数”的理解基本正确，不过，**参数更新与保存到磁盘是两个不同操作。**

**（1）磁盘负责持久保存，内存和显存负责运行时使用。**

这和常规程序的关系很相似：

> 从磁盘读取文件 → 在内存中处理数据 → 把结果保存回磁盘。

LLM 也遵循这个思路：

| 存储位置 | 主要作用 |
|---|---|
| 磁盘，例如 SSD | 保存模型权重文件，程序退出后仍然保留 |
| 系统内存 RAM | 供 CPU 使用，参与模型加载、数据处理等 |
| GPU 显存 | 存放 GPU 计算所需的参数和中间数据 |

所以，**磁盘上的模型文件和显存中的运行时参数，可以同时存在。** 加载模型，并不会把磁盘上的文件删除。

**（2）在常见的 GPU 训练中，确实会反复使用和更新显存中的参数。**

以模型能够放进单张显卡的情况为例，可以这样理解：

```text
磁盘上的模型权重
        ↓ 加载
GPU 显存中的模型参数
        ↓
使用当前参数进行计算
        ↓
计算损失和梯度
        ↓
优化器更新可训练参数
        ↓
使用更新后的参数，处理下一批数据
        ↓
反复进行……
```

**训练本身就包含参数更新。** 不是先“训练一下”，再由人手工“调一下参数”，而是训练程序自动完成这个循环。

如果使用 LoRA，循环中更新的主要是新增的适配器参数，原始模型权重保持冻结，但仍参与计算。

**（3）会保存到磁盘，但通常不是每更新一次参数就同步一次。**

训练程序一般按配置保存 **checkpoint（检查点）**，例如每隔一定数量的训练步保存一次，或者每完成一轮训练保存一次。也可以在训练结束时主动保存。

假设设置每 500 步保存一次：

```text
第 500 步：保存检查点到磁盘
第 501～999 步：继续在运行时更新参数
第 1000 步：再次保存检查点
```

如果在第 800 步突然断电，通常可以从第 500 步的检查点恢复，之后尚未保存的更新就会丢失。

用于继续训练的检查点，通常还会保存优化器状态、训练进度等；只导出模型用于推理，则不一定需要这些训练状态。

教材 **11.6.4** 中的：

```python
merged_model.save_pretrained("./models/merged_model")
```

就是把合并后的模型保存为磁盘文件。

**（4）放在显存中，主要是为了让 GPU 高效计算。**

“需要反复动态调整”的理解是对的，但还需要补充一个原因：**LLM 训练涉及大量矩阵运算，GPU 擅长并行执行这些计算。** 把参数放在 GPU 附近的显存中，可以减少反复搬运数据的开销。

“参数量巨大”意味着需要更多存储空间，并不意味着参数必须全部放在同一张显卡里。也可以使用 CPU 训练、多张 GPU 分担，或采用其他内存管理方式。

因此，可以这样理解：**磁盘保存模型的持久版本；训练时使用内存或显存中的运行版本，反复计算和更新，再按保存策略把阶段性结果写回磁盘。**

补充参考：[Hugging Face：检查点保存](https://huggingface.co/docs/transformers/trainer_recipes)，关于按训练步数或轮次保存检查点的说明。


## 4. 为什么本章的训练、评估主要调用 rl_tool.run()，没有展开内部实现？

对应教材：**11.1.4 HelloAgents 的 Agentic RL 设计**、**11.1.5 快速上手示例**、**11.2.3 自定义数据集和奖励函数**，以及 **11.6.1 端到端训练流程**。

### 疑惑

- 第 11 章提到的各种训练、评估，其实都是调用 `rl_tool.run()` 并传递不同参数实现的，没有说明实际的实现代码，是吗？
- 为什么文章采用这种设计？真正的训练和评估代码在哪里？

### 解答

**第 11 章的主要训练、评估示例，展示的是如何调用 `RLTrainingTool`，没有逐层展开训练器内部的完整实现。** 不过，它也提供了自定义奖励函数、数据处理、训练流水线等部分实现。

**（1）`rl_tool.run()` 是统一入口，实际工作被封装在后面。**

教材 **11.1.4** 介绍了数据集层、奖励函数层、训练器层和统一接口层。你看到的 `RLTrainingTool`，就是最上面的统一接口。

按教材描述，可以这样理解它的分工：

```text
你编写的示例代码
    ↓ 传入操作和训练配置
RLTrainingTool.run(...)
    ├─ load_dataset：加载、整理数据
    ├─ create_reward：配置奖励函数
    ├─ train + sft：进入 SFT 训练流程
    ├─ train + grpo：进入 GRPO 训练流程
    └─ evaluate：进入模型评估流程
```

因此，**同样调用 `run()`，并不意味着训练和评估使用同一套算法，只是它们共用一个入口。**

比如传入 `"algorithm": "sft"`，相当于告诉框架“选择 SFT 这条执行路径”。后面仍然需要实际代码完成模型加载、计算损失、更新参数等工作。这些工作被封装起来了。

**（2）作者明确说明了：这一章侧重学会应用。**

在 [11.1.5 快速上手示例](<../../hello-agents/docs/chapter11/第十一章 Agentic-RL.md>) 中，原文直接写道：

> 由于这一章的理论部分比较多，实战需要调试的地方也十分繁琐，因此不专注于构造工具而是学会应用。

所以，这是一种明确的教学取舍。第 7 章比较侧重“搭建自己的框架”，第 11 章则把重点转向：

- 理解 SFT、LoRA、GRPO 分别做什么。
- 准备训练数据，设计奖励函数。
- 配置并执行训练。
- 评估效果，分析问题，再调整实验。

如果同时展开底层训练实现，还会涉及张量计算、自动求导、优化器、生成采样、显存管理等内容，篇幅和学习难度都会增加。

**（3）它讲了“为什么这样训练”和“怎样使用”，但实现细节确实有空缺。**

可以把本章覆盖的层次分开看：

| 层次 | 本章的呈现方式 |
|---|---|
| 算法原理 | 介绍 SFT、LoRA、GRPO 的思想和公式 |
| 实验配置 | 展示数据、学习率、批大小、奖励等参数 |
| 流程组织 | 展示 SFT → 评估 → GRPO → 评估的流水线 |
| 部分可扩展逻辑 | 提供自定义数据和奖励函数等代码 |
| 训练器内部实现 | 主要交给框架，没有完整展开 |
| 评估内部实现 | 讲指标与结果分析，但主要通过封装接口执行评估 |

例如，**11.2.3** 确实写出了一个奖励函数：提取答案中的数字，与标准答案比较，再计算奖励。但“如何把这些奖励变成损失、计算梯度并更新模型”，没有以完整的底层训练代码贯穿展示。

因此，“参数到底在哪一步被改变”“数据怎样变成训练信号”，正好属于这一章没有充分展开的实现层。

**（4）如果要理解底层，需要继续沿调用关系往下看。**

对于训练部分，阅读方向可以是：

```text
RLTrainingTool 的训练入口
    ↓
```
